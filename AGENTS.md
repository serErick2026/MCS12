# AGENTS.md — Rules for AI-Assisted Development

Project: School Safety Intelligence and Notification System (research
prototype, repository `MCS12`). Read this file before making any change.

## 1. Approved stack — do not substitute

- Frontend: HTML5, CSS3, vanilla JavaScript (ES modules). Lightweight component
  approaches only with explicit justification and approval.
- Hosting: Cloudflare Pages. Backend: Cloudflare Pages Functions (Workers
  runtime). Database: Supabase PostgreSQL. Auth: Supabase Auth.
- Algorithms: plain JavaScript modules.
- Free tier only. No paid services, paid APIs, paid libraries, or
  subscription-dependent features. No new dependency without approval.

## 2. Phase discipline

- Current approved phase: **Phase 2 — in progress, starting with the Git
  workflow** (`docs/git-workflow.md`); Phase 1 initialization is complete
  (see `docs/development-roadmap.md`).
- Do not implement hazard reporting, dashboard, incident correlation, risk
  scoring, notifications, or analytics until explicitly approved.
- No scope expansion without explicit approval.
- Do not deploy automatically. Deployment requires a human command.

## 3. Security rules

- Never hardcode credentials. Use placeholders only; never invent project IDs,
  URLs, API keys, or account details.
- **Approved exception:** `wrangler.toml` `[vars]` carries the Supabase
  `SUPABASE_URL` and publishable/anon key. Cloudflare Pages treats
  `wrangler.toml` as the source of truth for Git builds, and the anon key is
  public by design (also shipped in `public/config.js`), protected by Row
  Level Security. The service_role key must never appear in any file.
- Never expose the Supabase service role key, database passwords, or secrets
  in `src/`, `public/`, or any client bundle. Browser code may use only the
  publishable/anon key.
- Never commit `.env`, `.env.local`, or `.dev.vars`.
- Row Level Security is mandatory on every table containing application data.
  Do not create permissive production policies. Do not disable or bypass
  authentication or authorization to simplify development.
- Synthetic sample data only. Never use real learner or personal data.
- Never run destructive database commands (`DROP`, `TRUNCATE`,
  `DELETE` without approval) against any shared project.
- Keep privileged operations in backend code (`functions/`).

## 4. File and code rules

- Prefer simple, readable JavaScript. No unnecessary frameworks or
  dependencies.
- Keep the application modular but not overengineered; follow the existing
  structure in `src/modules/`.
- Do not overwrite or delete existing files without explaining the change in
  the final report.
- Do not create redundant or unused configuration files.
- Document configuration in `README.md`, `.env.example`, and comments in
  configuration files.
- Approved documents live in `docs/` — do not paraphrase or fabricate their
  content; store approved text as received.
- Build artifacts (`public/src/`, `public/config.js`) are generated by
  `npm run build` and are gitignored — edit `src/`, never the copies.

## 5. Workflow requirements

- Run checks before reporting completion: `npm test` and `npm run build`.
- Inspect the repository before changing it; preserve existing files unless a
  change is necessary and explained.
- After each task, report: files created/modified, purpose, validation
  results, and any unresolved decisions.
- Stop at phase boundaries and wait for approval before starting the next
  module.
- Git workflow (approved 2026-10-04): `main` is the stable production
  branch — pushes/merges to `main` may trigger an automatic production
  deployment on Cloudflare Pages. `feature/*` for approved functionality,
  `fix/*` for bug fixes, no `develop` branch. All feature work goes through a
  reviewed pull request before merging into `main`. Database migrations and
  RLS policies require explicit human review. Full rules:
  `docs/git-workflow.md`.
- Do not create, merge, delete, or push branches without explicit approval.

## 6. Key commands

| Command | Purpose |
| --- | --- |
| `npm install` | Install dev dependencies (wrangler) |
| `npm run build` | Generate `public/src/` and `public/config.js` |
| `npm run dev` | Local Pages server with Functions on port 8788 |
| `npm test` | node:test checks including secret scan |
| `npm run deploy` | Manual deployment (env vars injected via temporary config) — never run unprompted |
